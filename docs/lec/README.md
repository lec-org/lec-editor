# LEC Editor 第一阶段与 Wu 改动评估

第一阶段目标是交付一个 Windows C/C++ 编辑器：保留 Zed 的文件操作流程，精简功能，并提供配套的编译运行环境。

当前只完成 fork 和固定版本的源码基线。本页记录已确认的产品范围与源码调研结果，所有产品功能均尚未实现或验收。

## 已确认的使用流程

- 沿用新建文件、打开文件、打开文件夹、文件树、标签页、搜索和终端。
- 新建空白文件默认按 C 处理，保存默认使用 `.c`；保存为 `.cpp` 后使用 C++。
- 首次运行未保存的文件时，使用正常的保存对话框；之后运行自动保存。
- 默认编译运行当前文件，同文件夹内其他带 `main()` 的独立文件不参与此次编译。
- 多文件工程沿用打开文件夹的流程；在实现时明确构建目标，不能无条件合并文件夹内的全部源文件。
- 运行终端支持输入、输出、退出状态和停止程序；编译失败时不能运行上次构建的产物。
- 基础工具链随安装包提供；库目录先覆盖少量验证过的库，并记录依赖版本。
- LEC 登录、文档入口和提交功能在后续阶段接入。

## 优先参考：模块裁剪

Wu 的早期裁剪同时修改了 Cargo 依赖、初始化代码、动作、快捷键和设置。可参考以下提交定位依赖边界：

- [移除协作和 AI 功能，b40b502d683f](https://github.com/dstrml/wu/commit/b40b502d683faabe21e48fa55297b6da8b566e14)。
- [继续清理协作基础设施，5bd2ed8ffd36](https://github.com/dstrml/wu/commit/5bd2ed8ffd36659e36eddd8d277301c62594e6ec)。
- [移除 miniprofiler_ui 及其启动入口，69b757b93d19](https://github.com/dstrml/wu/commit/69b757b93d19ce23354cdf5e10660d32cf772538)。

LEC 的实施方式：先明确保留的模块，使用现有设置关闭无关入口，再按依赖逐项移除初始化和编译依赖。`v1.28.1` 已有 `disable_ai`、标题栏登录入口和遥测设置，但这些设置本身不能证明相应依赖已经从二进制移除。

这些历史提交跨越大量代码，不能直接整包套用到 Zed `v1.28.1`。也不采用提交标题中的内存降幅作为 LEC 性能承诺。保留本地日志和必要的故障排查能力。

## 优先参考：中文化基础设施

[中文化提交 babb8f2d27f8](https://github.com/dstrml/wu/commit/babb8f2d27f82fdfe0bb29b25ead07338e09b2b0) 增加独立 `i18n` crate 和中文词条。当前 [i18n 实现](https://github.com/dstrml/wu/blob/v1.2.2/crates/i18n/src/i18n.rs) 包含：

- 常规翻译与带上下文的翻译入口。
- 缺少译文时回退到英文。
- 参数占位、语言选择与调用位置缓存。
- 用于查找遗漏翻译的伪语言模式。

这些机制适合借鉴。移植时只覆盖保留的文件、编辑、搜索、终端、设置及新建运行入口，避免把 Agent 等无关界面一并带入。语言切换与缓存、中文字体回退和文本长度需要单独验证。

## 优先参考：Windows 安装与运行细节

[安装器标识修复 51d2b89af114](https://github.com/dstrml/wu/commit/51d2b89af1145588275b95175582db99c952791a) 修复了 Wu 与 Zed 共用标识导致安装位置混用的问题。LEC 必须使用独立的安装器 ID、Explorer 扩展标识、应用标识、设置目录、文件关联和更新来源，并测试与 Zed 同时安装、升级及卸载。

[后台进程启动修复 3a71e7edfd27](https://github.com/dstrml/wu/commit/3a71e7edfd27) 为 Wu 的 Agent 后台进程统一设置 Windows `CREATE_NO_WINDOW`。LEC 可借鉴其集中封装的方式来启动编译器和工具探测，避免额外控制台闪现。交互式 C/C++ 程序仍需通过终端启动和接收输入，不能把这个标志无差别套到所有子进程。

[窗口尺寸持久化修复 9c5150426591](https://github.com/dstrml/wu/commit/9c5150426591) 让默认窗口尺寸更新更一致。先在选定的 Zed 版本上复现对应问题，再决定是否移植。

## 后续评估：搜索内存与性能测量

[搜索内存优化 24b9110aa9d2](https://github.com/dstrml/wu/commit/24b9110aa9d2e462e66786c01eb832f9613807d8) 对搜索结果中的文件延迟语法解析，显示到屏幕时再解析，同时修正大纲、面包屑及诊断等待首次解析的行为。这是具体的性能优化候选，但影响编辑器与语言层，优先级低于编译运行闭环。

[Wu 的测量文档](https://github.com/dstrml/wu/blob/v1.2.2/docs/memory-benchmark.md) 区分空闲、搜索、大文件和终端输出，统计整个进程树，并给出复现脚本。它测的是 Wu `1.0.10` 与 Zed `1.21.0` 等版本，在 Linux ARM64 软件渲染环境运行，工作流测试关闭语言服务；结果不能外推为我们的 Windows C/C++ 编辑器性能。

LEC 应在 Windows 实机上统计编辑器、clangd、编译器及运行程序的整体占用，覆盖启动、编辑、编译、搜索和大量终端输出。

## 移植顺序与验证

建议顺序：独立应用标识与更新边界 → 功能入口及后台模块裁剪 → 核心中文界面 → 默认 C 文件和编译运行 → 少量库管理 → 根据实测决定性能优化。

每项源码移植记录 Wu 的提交及改动目的，先检查当前 Zed 是否已有等效实现，移植后验证相关行为。保留许可证和作者归属。当前没有导入任何 Wu 源码，也没有进行编译、运行或性能测试。

下一步从 [固定的 Zed 基线](../../UPSTREAM.md) 进行 Windows 构建验证，再实施独立标识和最小功能裁剪。
